**日期**：2026-10-06
**范围**：OpenLEMS 用户侧（园区 / 大型商场）储能充放电策略

---

## 一、背景与结论

目标场景为**用户侧储能**：装在电力用户计量关口内，服务工业园区或大型商场的储能设备，用于**降低自身电费**。

### 关键结论

| 维度 | 结论 | 依据 |
|---|---|---|
| 储能类型 | **用户侧储能**（表内） | 参考资料《电力现货市场——未来储能运营商业模式的核心》第 3 页分类表 |
| 电价制度 | **两部制**（含基本电费 / 需量电费） | 园区 / 商场变压器容量通常 ≥100kVA；`0618交流PPT.md` 案例"控制目标需量 1900kW" |
| 电价形态 | **固定分时峰谷电价**（已知，无需预测） | 现行工商业用户以固定分时电价为主 |
| 光伏 | **可选**，设计上按"有光伏为主流"处理，做成可选输入 | 参考资料将"光储最优容量规划"单列为一个业务方向 |

### 核心判断

> **用户侧储能的电价是固定且已知的，不需要预测电价。**
> **真正需要预测的是园区负荷曲线**（用于需量控制与峰谷套利时机微调）。

这与"现货市场储能"（电网侧）的技术路线完全不同：电网侧赚市场价格差、需参与现货市场报量报价；用户侧赚自身电费差、不参与市场。

### 收益来源

```
收益 = 峰谷价差套利 + 需量电费节省 − 循环损耗成本
```

1. **峰谷套利**：谷段充电、峰段 / 尖峰放电，省 `(峰价 − 谷价) × 放电量 × 效率 − 损耗`
2. **需量控制**：两部制下基本电费按月最大需量（kW）计收，储能放电削峰可压低最大需量

## 二、设计原则

**所有可变因素做成配置，不做代码分支，以服务"一类客户"而非单个项目。**

| 配置项 | 说明 | 来源 |
|---|---|---|
| 电价时段 | 谷 / 平 / 峰 / 尖峰 / 深谷 | 现有 `price` 表，`SPriceSegment` 已支持 |
| 储能参数 | 功率容量、能量容量、SOC 上下限、效率 | 设备寄存器 `0xD1–0xD5` 实时读取 |
| 是否有光伏 | 可选 PV 数组，默认全 0 | 客户配置；一套模型通吃有 / 无光伏 |
| 需量控制开关 | 是否启用、需量目标值、需量电价 | 按省预设 + 客户可覆盖 |
| 变压器参数 | 容量、安全系数 | 现场配置 |

### 参数来源

- **设备寄存器**（`ess_demo_v1.0.0`，见 `emsdevice/internal/essdemo/map.go`）：

  | 参数 | 点位 | 单位 |
  |---|---|---|
  | 功率容量 `P_max` | `PowerCapacity` @ `0xD1` | kW |
  | 能量容量 `E_max` | `EnergyCapacity` @ `0xD2` | kWh |
  | 最大充 / 放功率 | `MaxChargePower` @ `0xCD` / `MaxDischargePower` @ `0xCE` | kW |
  | `SOC_min` / `SOC_max` | `MinSOC` @ `0xD3` / `MaxSOC` @ `0xD4` | % |
  | 充放电效率 | `ChargeEfficiency` @ `0xD5` | scale 0.01 |

- **策略参数**（设备无，给默认）：
  - `SOC_0` 每日起止电量比例：默认 `SOC_min`（纯套利场景）
  - 单日满充满放次数上限：默认 1–2 次，可配置

### 优化目标

```
max  Σ [ 峰谷价差 × 放电量 × 效率 ] + 需量节省 − 循环损耗
s.t. P_max, E_max, SOC_min/max, SOC_0, 日循环次数上限
     关口功率 ≤ 需量目标值
门槛：预测峰谷价差 < 阈值 → 不动作
```

## 三、模型定位

| 环节 | 方案 |
|---|---|
| 负荷预测 | **TimesFM 预测园区负荷曲线**（日前 96 点 / 15min），作为需量控制与套利优化的输入 |
| 电价 | 从 `price` 表读取固定分时电价，**不预测** |
| 优化求解 | 规则 / 线性规划，输出 `[小时, 功率%]` 计划 |
| 下发 | 复用现有 `ExecuteStrategy` 通道 |

> 备注：TimesFM 用于预测**负荷**而非电价；天气对负荷预测有价值（与此前"城市天气对电价预测无用"的结论不冲突）。
