# EMS 前端重构 · 产品界面设计

- 日期：2026-10-06
- 状态：方案（待评审）
- 可点原型：`prototype/index.html`（单文件、无依赖、浏览器直接打开；数据为 mock）
- 参考：[山西电力现货市场交易决策支持系统简介](../../../../dairy/mdstorage/domain/电力/山西电力现货市场交易决策支持系统简介.md)
- 目标壳层：企业后台「顶部 Tab → 左侧侧栏 → 主界面」

## 1. 现状与问题

现网前端是 `application/manifest/web.zip`（Vue + Arco，预编译，无源码），能力靠 `manifest/overlay/*.js` 运行时注入补齐。

现状导航是**卡片墙 + 返回首页**：

```
首页 Dashboard
   └─ System Management（卡片墙）
        ├─ Basics:  Real-time Data / Alarm List / Log Viewer / Statistics
        └─ Management: Strategy / Remote / Automation / Price / Protocol
                       Driver / Network / System Management
```

问题：

| 问题 | 表现 |
| --- | --- |
| 无全局导航 | 每个管理页只有「Back to Home」，层级靠记忆，跨模块跳转要回首页 |
| 状态不保留 | 页面切换即丢弃筛选/日期/滚动位置 |
| 模块不可组合 | 现货日报、现货趋势、效果评估、负荷预测各自为政，无法同屏对照 |
| 导航硬编码 | 侧栏/Tab 若是写死模板，接一个新模块要动多处 |
| 视觉不成体系 | overlay 直接用 Arco CSS var 拼，缺统一间距/密度/空态规范 |

对齐山西参考系统的关键取舍：它用**顶部 Tab 收纳 7 大模块**、**左侧「快速导航」复选框驱动主区面板**、**每个模块一个可拖拽浮层（`信息披露 ×`）**。这三条正是本次要复用的骨架。

## 2. 设计原则

1. **两层导航，不进不出的稳定感**：Tab 只换模块，侧栏只换页面；任何跳转最多回退两级。
2. **一屏可组合**：主界面是面板网格（12 栅格），用户可勾选/排列，看板即配置。
3. **时间上下文全局化**：日期区间在 Tab 头部一次设定，Tab 内所有图表继承。
4. **导航即数据**：Tab / 侧栏 / 路由 / 权限码来自同一份 `nav` 配置，新增模块只加一条。
5. **不打断**：编辑器走右侧抽屉（drawer），详情走主区，强确认才用模态框。
6. **顶栏克制**：AppBar 只放身份与入口（Logo、站点、用户）。流量/CPU/时钟这类实时指标不进顶栏，放「配置 · 系统信息」页。顶栏越素，主区越显眼。

### 3.3 导航即数据

```ts
// nav.ts —— 唯一真源：Tab、侧栏、路由、面包屑、权限、图标全从这里出
export interface NavItem {
  key: string
  title: string
  icon?: string
  route?: string          // 叶子；有 children 则为分组
  perm?: string
  badge?: () => number     // 告警数、未复核项数
  children?: NavItem[]
}
export const NAV: { key: string; title: string; icon: string; children: NavItem[] }[] = [ /* §3.2 */ ]

// scene.ts —— 场景切换器候选；每个场景声明 7 模块各自的数据源。
// 场景只影响「场景」Tab 的主区内容，不改侧栏结构
export interface Scene { key: string; title: string; sources: Record<string, string> }
export const SCENES: Scene[] = [ /* 广东现货日报 / 山西现货交易 / 储能套利 */ ]
```

新增一个页面 = 一条 `NavItem` + 一个路由组件；新增一个场景 = 一条场景配置。不改壳层。

尺寸与行为：

| 区 | 高度/宽 | 行为 |
| --- | --- | --- |
| ① AppBar | 56px | 固定；左 Logo + 站点切换，右用户菜单。**不放流量、CPU、时间这类实时指标**（它们属于「配置 · 系统信息」页）。移动端收成汉堡 + 标题 |
| ② Tabs | 44px | 固定；激活项下划线 2px 主色；窄屏横向滚动，不换行 |
| ③ Sidebar | 220px / 收起 56px | 可收起为图标轨，hover 出文字；状态存 localStorage |
| ④ PageHeader | 56px | 吸顶；左标题+面包屑，右操作；随滚动阴影 |
| ⑤ Content | flex:1 | 独立 `overflow-y:auto`；内边距 16px；栅格 gap 14px |

沿用现网视觉基因（与 `web.zip` 同源，Arco 风格），但补齐**阶梯**与**对比度**两项：

```css
/* —— 间距：只允许取这些值 —— */
--s1:4px; --s2:8px; --s3:12px; --s4:16px; --s5:24px; --s6:32px;
/* —— 字号：6 级 —— */
--fs-12; --fs-13; --fs-14; --fs-16; --fs-18; --fs-22  /* 页标题 18 / 面板标题 16 / 正文 14 */
/* —— 圆角：3 级 —— */
--r-xs:2px;  /* 面板左侧竖条 */
--r-sm:6px;  /* 控件、按钮、输入 */
--r-md:10px; /* 面板、卡片 */

/* —— 颜色 —— */
--bg-1:#f7f8fa; --bg-2:#fff; --bg-3:#f2f3f5; --bg-4:#fafbfc;
--border:#e8eaee; --divider:#f0f1f4;
--text-1:#1d2129; --text-2:#4e5969; --text-3:#626c78;
/* 品牌橙分三档：填充/竖条/图表用亮档，承载文字时换深档 */
--brand:#ff7d00;       /* 只用于填充、竖条、图表 */
--brand-ink:#b85000;   /* 浅底上的品牌文字（白底 5.0:1） */
--brand-btn:#c25400;   /* 白字按钮底（白字 4.6:1） */
--brand-soft:#fff7e8; --brand-line:#ffd9a8;
--accent-bar:2px;
```

**硬性约束（改样式前先看）**：

1. 间距/字号/圆角一律取上面的阶梯，不写 `14px`、`13.5px`、`9px` 这类一次性值。
2. `--brand` 不承载文字；文字用 `--brand-ink`，按钮底用 `--brand-btn`。
3. 正文与辅助文字对比 ≥ **4.5:1**（`--text-3` 在白底 5.3:1、`bg-3` 上 4.8:1 已卡到线）。
4. 彩色底不用白字（除 `--brand-btn`）：标签/甘特条改用「浅底 + 深字」（`*-soft` + `*-ink`）。
5. 边框只做一层：面板有边框，内部卡片用浅底（`--bg-4`），不再叠第二层边框。

### 4.2 面板（Panel）规范

所有内容都是面板，统一四件套：

```
┌─▍标题 ─────────────────────── 副标题/徽标  ─ ─  [⋯] ┐   ← head 44px，左 4px 主色条
│                                                     │
│   body（图表 / 表格 / 表单）                          │
│                                                     │
└─ 数据来源：LEMS  · 更新于 18:58 ────────────────────┘   ← foot 28px，灰字
```

- 空态：居中一句话 + 一个主行动按钮，不画占位骨架超过 1 秒。
- 加载：骨架块保持面板高度，避免跳版。
- 错误：面板内联红字 + 「重试」，不弹全局 toast。
- 徽标：未复核项数、排除条数等，用中性灰 chip，不用红色（红色留给真告警）。

1. **市场切换**：单选项 `日前 / 实时`，默认日前。切换只刷新数据，不回页顶。
2. **日期选择器**：单日 `date`，`max` = 今天，默认昨天；未来日期置灰不可选（避免空白）。
3. **KPI 条**：六张卡一张一行，`2:2:2:2:2:2`。每卡右下角灰字写口径，hover 出完整 tooltip。
   - 天气：图标 + 文字，副标最高/最低气温；无数据时显示 `—`。
   - 新能源：`n MWh`（口径：风电 + 光伏发电量）。
   - 最大负荷、最大净负荷：`n MW`，取当天 96 点峰值。
   - 供需比：显示为 `n : n`（如 `1.16 : 1`），比例保留两位小数，分母归一到 1；副标注明口径（总负荷 / 净负荷）。
4. **市场运行边界**：三线同图——新能源出力（面积）、总负荷（实线）、净负荷（实线）；x = t1…t96，y 单位 MW；共享 tooltip 十字线，图例可点隐藏。
5. **市场供需比**：柱 = 净负荷（左轴 MW），线 = 供需比（净负荷口径，右轴比值），双 Y 轴；柱线同色系不抢眼。
6. **火电启停统计**：环形图，四分类 `必开 / 必停 / 市场竞争已开 / 市场竞争已停`，圆心显总台数；点扇区 = 下图过滤条件。
7. **火电启停表**：列 `机组名称 / 机组状态 / 容量(MW)`；支持搜索、状态筛选、全选、导出 CSV；表头吸顶。

| | 日前 | 实时 |
| --- | --- | --- |

## 7. 技术选型与落地

选型：`Vue 3 + Vite + TypeScript + Arco Design Vue + ECharts + Pinia + vue-router`。

理由：与现网 `web.zip`（Arco/Vue）同源，视觉零迁移成本；overlay 脚本依赖的 CSS var、`ems:user:token`、`/api` 全部保持不变。

**源码位置：`OpenLEMS/web/`**（`npm run build` 的 `dist/` 与现网 web.zip 同构，打包后覆盖 `application/manifest/web.zip`）。CI：`.github/workflows/web-ci.yml`（typecheck + build + 壳层冒烟）。

**P0 已落地**（本篇写完时）：

- `src/nav/index.ts` 导航唯一真源 → 路由表由它生成，不手写第二份
- AppBar / TabBar / SideNav / PageHeader / PanelBox / KpiCard / StatusTag + AppShell
- `src/styles/tokens.css`：间距·字号·圆角阶梯 + 对比度达标色板（与 §4.1 一致）
- 信息披露页接了真实数据（`GET /api/gd-metric`）；其余 28 页落 `PlaceholderView`，按 nav 里声明的面板列结构 + 标状态
- 壳层冒烟：happy-dom 加载**构建产物**，逐个点过 29 页断言标题 / 占位面板 / 顶栏约束

**Arco 的取舍**：P0 与手动控制页（第一批表单）都**没有**注册 Arco 全局组件。实测
全量 `import ArcoVue` + `arco.css` 会让 CSS 从 **8KB 涨到 404KB**、JS 从 **108KB 涨到 872KB**。
按需引入单组件样式可把 CSS 压在百 KB 内，但本项目的 tokens + 手写控件已覆盖
「输入 / 下拉 / 开关 / 卡片」，且对比度是算过的；引入 Arco 反而多一轮视觉对齐。

**结论：Arco 留到真正需要复杂组件时再引**（树、日期区间、虚拟滚动表格）。
`styles/arco-override.css` 已把 Arco 变量对齐到本项目色板，届时按需引入不会产生视觉漂移。

**已实现的页面**（其余按 nav 声明落占位页）：

| 页面 | 接的接口 |
| --- | --- |
| 场景 · 信息披露 | `GET /api/gd-metric` |
| 管理 · 手动控制 | `name-list` / `control/custom-services` / `device/telemetry` / `device/history` / `control/device` |
| 配置 · 储能参数 | `GET /api/policy/config-fields`（字段元数据）+ `GET /api/policy/config`（当前值）+ `POST /api/setting/update`（保存） |

**新增接口 `GET /api/policy/config-fields`**：储能参数的表单字段元数据由后端**反射
`SPolicyMircogridConfig` 的 struct tag** 得到（`name` / `ct` / `vt` / `min` / `max` /
`default` / `unit` / `group`），返回字段列表与分组顺序。前端不复制第二份字段表 ——
加字段只改 Go struct，表单自动跟上。顺带补齐了 struct 里缺失的
`vt`（`essDevices` / `gridDeviceId` / `forecastBaseUrl`）与 `group` 标签。

**储能参数 → 手动控制的保护闭环**：手动控制页读同一份配置，推导出
「SOC 允许区间」「功率上限 = 设备额定 × 配置比例」，下发前一并校验；
被拦时提示来自哪一条约束（驱动声明的 max，还是储能参数推导的保护上限）。
「语义级」保护（判断该指令是充还是放）需要驱动声明充/放语义，目前没有，不做也不假装。

手动控制页的口径（写死在代码注释里）：服务与参数全部来自**驱动声明**，前端不写死
「充电 / 放电」；`parameters` 是**位置参数数组**，顺序必须与驱动声明一致，下线前二次确认。
EMS 侧的跨设备保护（SOC / 变压器 / 需量）要等「配置 · 储能参数」接口，现在只用
驱动自己声明的 `min/max/required`，不假装有。

### 11.4 管理/配置的共用规矩

1. **生效语义必须写明**：每张配置卡右上角标 `立即生效 / 重启后生效 / 下次采集生效`。不标就是坑。
2. **改前看 diff**：配置型提交前弹差异预览（旧值 → 新值），确认了才应用。
3. **危险操作输名确认**：删除 / 停机 / 清空 / 恢复出厂，需输入对象名才可提交（比“确认弹窗”多一道）。
4. **密钥只写不读**：保存后展示为 `••••`，无「查看」；更新需重输。
5. **审计日志**：每次增/改/删写一条操作日志（谁 / 何时 / 对象 / 旧值 → 新值）；入口在「管理 · 审计」，可筛「配置变更」。
6. **干跑 / 试运行**：策略与自动化支持拿历史数据试跑，不实际下发指令。
7. **共用选择器**：设备选择器、点位选择器、时段选择器、算法选择器各写一个，全站复用（这是最容易各写一遍的地方）。
8. **导入导出**：列表页统一支持导出 CSV、导入（带校验预览），点表与配置尤其需要。
9. **状态徽标**：启用/停用、在线/离线、已确认/未复核——全用同一个 `StatusTag` 组件，不各页各写。
10. **权限到按钮**：无权限的操作按钮直接不渲染，不留灰态（与侧栏一致）。

## 14. 策略反演 / 长周期电价预测：数据源与建模

### 14.1 策略反演需要什么数据

前提：市场主体的**报价不公开**。反演 = 从**观测到的出清结果**反推“他报了什么价”。参考 `网侧储能现货市场决策支持系统技术路线概述.md` 的「市场成员报价策略推演」（1.3.2）与 `0903…` 的策略反演案例。

| 类 | 需要的数据 | 典型来源 | EMS 现状 |
| --- | --- | --- | --- |
| 出清结果 | 每时段出清价 P、中标电量 Q、出清机组组合 | 交易中心披露 / 日报 | 🟡 部分（日报表1(二)/表2 + 节点电价档位） |
| 网络模型 | 电网拓扑、线路/断面限额 | 电网 / 规划 | ❌ |
| 节点价格分解 | 电能量价格 + 阻塞价格 | 出清结果 | 🟡 部分（山西有城/节点价） |
| 机组参数 | 容量、最大/最小出力、爬坡、启停成本、边际成本、煤耗 | 机组台账 | ❌ |
| 机组状态 | 开机/停机、实时出力、累计电量 | 现场采集 | ✅ EMS 现场数据 |
| 运行边界 | 负荷预测、新能源出力预测、外送计划、检修 | 日报 / 预测 | 🟡 部分 |
| 市场规则 | 出清模型（SCUC/SCED）参数、报价上下限、价格帽、申报格式 | 市场规则 | ❌ |
| 历史报价（可选） | 主体申报曲线 | 交易中心（一般不公开） | ❌ |

**两种反演方法**：

1. **逆优化（反演）**：把出清模型当约束，找使观测结果最优的报价曲线。最可信，但**必须有网络模型 + 出清模型 + 机组成本**。
2. **统计/机器学习拟合**：用历史出清价 + 边界 + 机组状态拟合报价曲线族（保守/稳健/激进/相似场景）。不保证与真实出清一致，只能作参考。

**输出**：报价段一…十 `(MW, 元/MWh)`、边际成本、策略族、收益概率分布。

**结论**：EMS 现在缺网络模型 + 出清模型 + 机组成本参数，**只靠日报做不了反演**。建议标 `TODO`，等接入市场仿真或拿到交易中心出清明细。可在原型里标 `TODO` + 一行说明。

### 14.2 长周期电价预测是什么 / 怎么建模

先分清两种“长周期”，产品里是两个东西：

| | 展望期 | 用途 | 出处 | 本期 |
| --- | --- | --- | --- | --- |
| **A. 未来多日滚动** | 5~15 天 | 交易决策 / 充放计划 | 山西「未来5日电价预测」= 本模块 | ✅ 要做 |
| **B. 长周期投资评估** | 年 / 15 年 | 投资收益、资产定价 | `0903`「15年长周期仿真」、网侧储能投资决策 | ❌ 另一条产品线 |

**A. 未来多日（本模块）**

特征：负荷预测、新能源出力预测、天气、检修计划、开机与燃料成本、外送计划、供需比。

```
    数据驱动（GBDT / LSTM / TimesFM） ─┐
                                      ├─ 融合/校正 ─▶ 96 点日前价格 + 分位带
    物理模型（SCUC/SCED 出清仿真）    ─┘
```

- 物理侧：出清仿真，出「理论价」（需网络 + 机组 + 边际成本）。
- 数据侧：时序模型，出「统计价」（本项目已有 TimesFM 负荷预测骨架，可扩到价格）。
- 融合：残差校正 / 加权 / 分场景切换。
- 区间：分位回归 P10/P50/P90 或 conformal prediction。
- 评估：1−MAPE 准确率（山西口径 93%，50% 场景 >95%）、峰谷方向命中率。

**最小可用版（无物理模型，能在 EMS 现有数据上先做）**：用历史日报价 + 负荷/新能源预测 + 日历特征，训一个 quantile GBDT，先出「日均价 + 分位带」，分时用日型模板展开。等数据积累再加物理侧。

**B. 长周期投资评估（另一个模块，本期不做）**

```
供需边界场景集（蒙特卡罗：负荷增长 / 新能源规划 / 燃料价格 / 政策 / 检修）
        ↓
多市场联合出清仿真（SCUC/SCED × N 场景）
        ↓
长周期电价概率分布（P10/P50/P90 × 年 × 时段）
        ↓
储能收益仿真 → IRR / 动态回收期 / 静态回收期
```

需要电源/电网规划、负荷增长、燃料情景、政策规则、出清模型——EMS 都没有。归为另一产品线（投资决策），不在本次前端范围。

### 14.3 结论

| 模块 | 本期 | 理由 |
| --- | --- | --- |
| 策略反演 | ❌ TODO | 缺网络/出清/机组成本；只靠日报无法反演 |
| 长周期电价预测（未来多日） | ✅ 做 | 有历史日报价 + TimesFM 骨架，可先上数据驱动最小版 |
| 长周期投资评估（年/15年） | ❌ 不做 | 属投资决策产品线 |

### 14.4 长周期电价预测 · 最小版步骤（数据驱动，立即可做）

**输入字段清单**（训练 + 推理）

| 字段 | 来源 | 粒度 | 角色 |
| --- | --- | --- | --- |
| 日前成交价（表1(二)） | 日报提取 | 96 点/日 | **目标序列 y** |
| 实时成交价（表2(二)） | 日报提取 | 96 点/日 | 辅助/对比 |
| 系统负荷 | 日报 / 边界 | 96 点/日 | 外生 |
| 新能源出力 | 日报 / 边界 | 96 点/日 | 外生 |
| 净负荷 | 计算 | 96 点/日 | 外生 |
| 备用需求 | 日报 | 日/时段 | 外生 |
| 检修 / 开机安排 | 日报 | 日 | 外生 |
| 天气 | **TODO 数据源** | 日 | 外生 |
| 日历（星期/节假日） | 生成 | — | 特征 |
| 燃料成本 | **TODO** | 日 | 外生（可选） |

**步骤**

1. 收历史日前价序列（≥ 7 天，建议 60 天以上），**一天一个点**。
2. 缺测处理：只看已确认（`origin=manual`，SQL 层已剔除未复核）；同一天多来源时优先 表1(二)，缺失回落到 表2(一)。
3. 调 TimesFM：`horizon = 预测天数`（默认 5，上限 30），`quantiles=[0.1,0.5,0.9]`。
   > 序列是**日均**不是 96 点，所以 horizon 单位是**天**。若将来日报提取了 96 点价格曲线，
   > 则改回 `horizon = 5 × 96 = 480 ≤ max_horizon 512`，一次调用出 5 日分时。
4. 后处理：分位带单调校验（q10≤q50≤q90）、价格帽/下限截断。
5. 校准：过去 N 天滚动回测 → 残差校正 / quantile 校准（conformal）。
6. 输出到场景页：日均柱（长周期电价预测-平均）+ 分位带；预测曲线虚线并标「预测」。
7. 评估：1−MAPE、方向命中；写进「预测复盘」。

**多外生变量**：服务端当前按一维序列用；负荷/新能源各自单独预测，然后在价格上做残差回归校正（即“数据驱动 + 后校正”）。若要把它们当特征，再做一层 GBDT 残差模型。
